### 交付物

### 关键技术决策
- **UI 自检方案**：`ImageRenderer` 渲染不出 ScrollView 内容 → 改用「离屏 NSWindow + NSHostingView + cacheDisplay」，2x 位图，无需屏幕录制权限。截图能力内建在 `--snapshot`。
- **数据源**：`brew services list --json`（状态权威）、`brew list --versions`（版本/是否安装）、`launchctl list`（PID）、`lsof -nP -iTCP -sTCP:LISTEN -Fpcn`（端口 + 进程名）。
- **PID 三级解析**：launchctl → lsof 命令名匹配 → 默认端口归属（JVM 服务允许 java+端口佐证）。**已弃用 pgrep**：本机 `pgrep -f` 会返回无关 PID（67337）。
- **刷新策略**：服务 4s 轮询；运行时（bun/fnm/`du -sk` 扫几百 MB）90s 缓存 + 手动刷新强制探测。

### 踩坑（写进 README，后续别重复）
1. `brew list --versions` 因不受信任 tap（roversx/tap）报 Error 且 **exit 1**，stdout 67 行有效 → 解析不能以 `ok` 为门禁。
2. **brew 7.0.3 的 label 变为 `sh.brew.<formula>`**（plist 也是 `sh.brew.*.plist`），旧 `homebrew.mxcl.*` 仍需兼容。这是通过「用 LaunchServices 启一个最小 app 跑 brew services start」发现的。
3. `lsof -Fpc` 拿不到端口，必须加 `n` 字段（`-Fpcn`）。
4. GUI app 无登录 shell PATH，Process 需自拼 PATH（含 `/opt/homebrew/bin`、`~/.bun/bin`）。
5. Bash 工具沙箱内 `launchctl` 不可用（`launchctl list` 空、`brew services start` 报 bootstrap exit 5），`open --args` 传参也被吞；验证真实会话行为要用临时 .app + LaunchServices 启动。

### 新增能力
- **三种托管方式**（`ServiceKind`）：`brew`（brew services）/ `managed`（服务坞生成 `~/Library/LaunchAgents/local.servicedock.<id>.plist`）/ `external`（系统域 LaunchDaemon，提权启停）
- **MongoDB**：`mongodb-community`、`mongodb-community@8.0`、`@7.0` 三条目（tap `mongodb/brew` 已存在，未安装）
- **RustFS**：`managed` 托管。**已实际 brew 安装 1.0.3**（`rustfs/homebrew-tap/rustfs`），实测启动 9000/9001、PID 8376、0.8s 起来；验证后已 stop 并删 plist，现为「已安装 / 已停止」
- **EasyTier**：`external` 托管。本机已装 `easytier-gui.app` 2.6.4 + 系统守护进程 `easytier-gui`（`/Library/LaunchDaemons/easytier-gui.plist`，RPC 15999，进程 545，config.d 为 root 所有的 TOML）
- **定时任务页**：launchd 三域（用户代理/系统代理/系统守护进程）+ crontab；规则翻译成人话 + 日历型算下次触发；加载/卸载、kickstart 立即运行、enable/disable、看 StandardOutPath 日志、Finder 显示 plist；系统域动作走 osascript 提权

### 关键技术发现（重要，别再踩）
1. **`launchctl print system/<label>` 普通用户可读** → 能拿 `state = running` / `pid` / `last exit code`，不必 sudo；`launchctl print-disabled system` 也可读，用来标记「已禁用」。**`launchctl list` 只列当前用户域**，系统守护进程（easytier）不在里面。
2. **RustFS formula 没有 `service do` 块** → `brew services` 完全不认；必须自写 LaunchAgent。`rustfs server --console-enable` 是布尔开关，**不能跟 `true`**（会被 clap 当 VOLUMES 位置参数，启动失败）。
3. **Homebrew 7 tap 信任**：`brew install rustfs/homebrew-tap/rustfs` 报 `Refusing to load formula … from untrusted tap`，需 `brew trust rustfs/tap`；已在安装流程里做「识别报错 → trust → 重试」。
4. **本机网络：git 走 HTTPS 会 HTTP2 framing 报错**，`git -c http.version=HTTP/1.1 clone` 正常。brew tap 自动 clone 会失败，我是手动 clone 后 `mv` 到 `/opt/homebrew/Library/Taps/rustfs/homebrew-tap` 再 `brew install`。
5. **Bash 工具沙箱禁 `launchctl` / `ps` / `crontab`**，且 `brew install` 会因 brew 自带 sandbox-exec 被拒（exit 71）。验证真实链路统一用「临时 .app 经 LaunchServices 启动 → 由它调用被测程序/脚本」的办法（`/tmp/ldrun3` 那套），应用本体在真实会话里一切正常。
6. `ps -Ao pid=,command=` 拿到的 command 含完整参数，进程名匹配要**先取第一个词再取 lastPathComponent**（否则 easytier 匹配不到，曾导致 easytier pid 为空）。
