## 傍晚：轮询降耗（A 缓存 + B 自适应间隔，用户选 C 全做）

### A. brew 结果缓存（新增 `Sources/Core/BrewCache.swift`）
- `brew --version`（66ms）与 `brew list --versions`（**332ms**）缓存 60s（`BrewCache.ttl`），`NSLock` 保护的 `final class @unchecked Sendable` 单例。
- `SystemProbe` 拆成两层：`brewVersions()` / `brewHomebrewVersion()` 走缓存，原实现改名 `brewVersionsRaw()` / `brewHomebrewVersionRaw()` 只给缓存调用（避免循环依赖）。
- 失效点：`BrewCatalog.install/uninstall`、`AppModel+Actions.installService`、`installFnm`、`AppModel+Tools.installMise` 成功后 `BrewCache.shared.invalidate()`。
- 效果（`--bench`）：单轮采集子进程 **6 → 4**，墙钟 **940ms → 532ms**。

### B. 自适应轮询（`AppModel`）
- 常量 `foregroundInterval = 4` / `backgroundInterval = 30`（都必须是 `nonisolated static let`，否则 nonisolated 纯函数引用会报错）。
- 纯函数 `AppModel.pollInterval(active:hasVisibleWindow:)` 便于自检；实例侧 `currentPollInterval` 用 `NSApplication.shared` 读 `isActive` + 是否存在「canBecomeMain && isVisible && !isMiniaturized」的窗口。
- `start()` 改成 `waitForNextTick()`：每次现算间隔，`Task.sleep` 包成可取消的 `wakeSignal`；`wake()` 取消它即可立刻重排。
- 唤醒来源：`didBecomeActive` / `didResignActive` / 窗口 `didMiniaturize` / `didDeminiaturize` / `didBecomeKey` / `willClose` 六种通知（`queue: .main` + `Task { @MainActor in }`）。
- 设置页「关于」加 `刷新频率` 行（显示当前生效秒数 + 后台秒数），中英词条已补（`刷新频率` / `%d 秒（后台 %d 秒）`）。

### 诊断工具与踩坑
- 新增 `--bench`（`Sources/Core/BenchRunner.swift`）：冷/热采集的子进程数与墙钟、两条 brew 命令单项耗时、轮询间隔四分支、**唤醒链路实测**（启动首刷 → 静置不刷 → post `didBecomeActive` 后立刻刷新）。

## mise 激活状态误报修复（20:30–20:40）

**用户反馈**：fish 里跑 `mise activate` 得到一屏 `set -gx` / `function ...`，以为是失败；服务坞 mise 页同时报「未激活 / shims 未在 PATH」。

**根因（两条独立问题叠加）**
1. `mise doctor` 的 `activated:` 只读**当前进程**环境变量。GUI App 不是从登录 shell 启动，恒为 `no`，所以拿它当判据必然误报。
2. `shims_on_path: no` 在新版 mise（2026.x）里属正常：activate 直接注入 PATH，`~/.local/share/mise/shims` 目录根本不存在（本机实测确认），不该当作「未激活」信号。
3. 用户实际状态：`~/.config/fish/config.fish` 里**没有任何 mise 配置**，`~/.local/share/mise/` 也是空，所以「未激活」这个结论本身是对的 —— 错的是提示语（让用户去跑 `mise activate`，而该命令只打印不执行）。

**实现**
- `MiseProbe.swift` 新增 `ShellActivation{shell, files, configuredFile, exists}`；`detectActivation()` 按 shell 扫启动文件里的 `mise activate`：
  fish = `config.fish` + `conf.d/*.fish`；zsh = `.zshrc/.zprofile/.zshenv`；bash = `.bashrc/.bash_profile/.profile`。
- `loginShell()` 用 `getpwuid(getuid())` 取（GUI 的 `$SHELL` 常是系统默认值），本机正确取到 `fish`。
- `MiseSnapshot`：`processActivated`（原 doctor 值，仅参考）+ `activations` + `loginShell` + `shimsDirExists`；`activated` 改为计算属性 = 进程已激活 **或** 任一 shell 文件已配置。
- `activationSnippet(shell)`：fish `mise activate fish | source`；zsh/bash `eval "$(mise activate ...)"`。
- `activationTarget(shell)` + `writeActivation(shell)`：幂等追加（文件已有 `mise activate` 就跳过），带注释 `# mise（由服务坞写入）`。
- `MiseView`：第 4 个 tile 从误导性的「shims」换成「登录 shell」；未激活时出橙色引导卡 —— 解释「activate 只打印、必须交给 shell 执行」、给可选中复制的命令 + 复制按钮 + 「写入 fish 配置」按钮 + 写入后 `source` 提示 + shims 说明。
- 新增 CLI `--mise-activate [fish|zsh|bash]`（与界面按钮同一条代码路径，便于验证与脚本化）。
- `--bench` 加「mise shell 激活检测」段：登录 shell / 激活判定 / 各 shell 配置状态 / 激活命令 / 写入目标 / shims 目录。

**实测**
- 写入前备份 `~/.config/fish/config.fish.bak-servicedock-20261025-203427`。
- `--mise-activate fish` 第一次：`已写入 ~/.config/fish/config.fish`；第二次：`~/.config/fish/config.fish 里已经有 mise activate，未做修改`（幂等 OK）。
- `fish -n config.fish` 语法通过；`fish -c 'mise activate fish | source'` 输出 `* fish / * powershell`，`command -v mise` 正常 → 激活链路通。
- `--bench` 判定由「未激活」变「已激活（fish: 已配置 -> ~/.config/fish/config.fish）」。
- 截图 `/tmp/m3.png` 确认 tile 显示「已激活 fish」绿色、引导卡自动消失。

**踩坑记录**：词条重复 key 会让 `L10nDictionary` 静态初始化 trap（本轮又踩一次：`已激活` / `未激活` / `命令` / `复制命令` 各重复一次）。加词条后必须 `grep -c "        \"key\":"` 查重。
